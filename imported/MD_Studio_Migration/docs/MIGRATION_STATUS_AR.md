# تقرير حالة تحويل PocketBuilder 0.145 إلى MD Studio — المرحلة الثالثة

## المصدر المتاح
المصدر الأساسي هو APK مترجم فقط، وليس مشروع Gradle الأصلي. يحتوي APK على DEX وموارد وأصول ومكتبات Android، لكنه لا يتضمن شجرة السورس الأصلية أو كود الخادم. لذلك MD Studio تطبيق مستقل أعيد تنفيذ أجزاء منه اعتمادًا على تحليل APK، وليس نسخة مطابقة مكتملة من PocketBuilder.

## ما أصبح موجودًا في مصدر MD Studio
- تطبيق Android مستقل باسم `MD Studio` وحزمة `com.amd.mdstudio` وهوية AMD Studio.
- واجهة عربية بأقسام المشروعات والاختبارات ومساحة العمل والبناء والمكتبة والإعدادات.
- عدة مفاتيح Gemini بتخزين مشفر عبر Android Keystore، وتبديل عند أخطاء الحصة والخوادم المؤقتة.
- حسابات GitHub متعددة مع تخزين الرموز مشفرًا، واختيار مستودع، وتنزيل مصدر المستودع ZIP، وتشغيل Workflow، وجلب التشغيلات.
- رفع مشروع Gradle إلى فرع مستقل `mdstudio/build-*` عبر Git Data API، وإضافة Workflow مخصص إلى الفرع الافتراضي عند الحاجة، ثم تشغيل البناء على الفرع الجديد.
- دعم Workflow لبناء Debug أو Release، وتشغيل اختبارات Unit Tests، ورفع APK كـ Artifact.
- قراءة Artifacts لتشغيل Workflow وتنزيل ZIP واستخراج APK داخله.
- تصدير APK المنزّل أو المبني إلى مكان يختاره المستخدم عبر Storage Access Framework.
- استيراد مشروع Gradle ZIP وفحص سلامة مسارات ZIP.
- مستكشف ملفات ومحرر نصي محدود بحد 512 KB وحماية جذر المشروع ومجلدات البناء.
- تشخيص بنيوي لملفات المشروع دون الادعاء بأنه اختبار تشغيل.
- محرك بناء مباشر اختياري يتطلب JDK/Gradle/SDK مبنية لتعمل على Android وABI الجهاز.
- جسر بناء محلي عبر Termux RUN_COMMAND، يصدّر المشروع إلى مجلد مشاركة ويشغل Gradle داخل Termux، مع استقبال النتيجة ونسخ APK.
- اختيار GGUF وجسر استدلال Llama عبر `llama.cpp` CLI داخل Termux بعد بناء المحرك محليًا.
- إعداد توقيع Release اختياري عبر GitHub Secrets. دون الأسرار ينتج Release غير موقّع.

## ما لم يكتمل أو لم يُختبر
- لم يتم نقل جميع واجهات ومحركات PocketBuilder الأصلية من DEX.
- لم يتم استعادة سورس PocketBuilder الأصلي أو كود خادمه.
- لم يتم دمج llama.cpp كـ JNI داخل APK؛ الاستدلال الحالي يمر عبر Termux CLI.
- لم يتم اختبار البناء المحلي عبر Termux أو تشغيل Llama على هاتف فعلي.
- لم يتم تنفيذ Gradle compilation أو إنتاج APK في بيئة إعداد هذه الحزمة لعدم توفر Gradle وAndroid SDK.
- لم يتم ربط حساب GitHub حقيقي أو تشغيل Workflow فعلي من داخل التطبيق.
- لم يتم تجهيز شهادة توقيع AMD Studio؛ المشروع يقبل شهادة المستخدم عبر أسرار GitHub.

## التحقق المنفذ على ملفات المصدر
- AndroidManifest.xml اجتاز تحليل XML.
- سكريبتا Termux اجتازا `bash -n`.
- `ProjectWorkspaceManager.kt` اجتاز ترجمة Kotlin مستقلة.
- لم تظهر أخطاء parsing صريحة في فحص ملفات Kotlin الكامل، لكن compilation كامل غير ممكن دون Android/Compose dependencies.
- لم يتم بناء APK أو اختباره على جهاز.

## ما يلزم لاستكمال التكافؤ
1. نقل الوظائف الأصلية شاشةً ومحركًا بعد شاشة ومحرك، من خلال تحليل DEX واختبارات سلوكية.
2. تشغيل Workflow على مستودع GitHub فعلي والتحقق من Artifact download.
3. اختبار Termux bridge على هاتف ARM64 مع مساحة تخزين وذاكرة كافيتين.
4. اختبار نماذج GGUF مختلفة على الهاتف وقياس RAM والحرارة والسرعة.
5. إنشاء هوية توقيع AMD Studio وتخزينها خارج المستودع.
6. إكمال وكلاء التنفيذ الآلي وتوليد الملفات وتطبيق التغييرات على المشروعات بعد الموافقة الواحدة.
