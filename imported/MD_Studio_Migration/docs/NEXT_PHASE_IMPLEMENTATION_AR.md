# تنفيذ المرحلة التالية في MD Studio

## ما أُضيف في هذه الحزمة

### GitHub
- التحقق من رمز الوصول عبر `/user`، ثم حفظ الرمز مشفرًا باستخدام Android Keystore عبر `EncryptedSecret`.
- حفظ أكثر من حساب GitHub والتبديل بين الحسابات المحفوظة.
- جلب المستودعات مع ترقيم الصفحات (حتى 500 مستودع في الاستدعاء الحالي).
- اختيار مستودع من واجهة الإعدادات.
- تشغيل `.github/workflows/mdstudio-build.yml` على الفرع الافتراضي للمستودع المحدد عبر `workflow_dispatch`.
- جلب آخر 10 تشغيلات للـWorkflow وفتح صفحة التشغيل على GitHub.
- يتطلب رمز GitHub صلاحيات مناسبة، وأهمها Actions: write لتشغيل الـWorkflow وContents: read لقراءة بيانات المستودعات. قد تختلف المتطلبات بحسب إعدادات المستودع والمؤسسة.

### استيراد مشروع وبناء محلي
- استيراد مشروع Gradle من ZIP إلى مساحة خاصة بالتطبيق.
- فحص ZIP ضد Zip Slip، مع حد أقصى لحجم الملفات المستخرجة 1 GB.
- استيراد حزمة أدوات بناء يجهزها المستخدم، مع فحص JDK وGradle وAndroid SDK وAAPT2.
- حزمة الأدوات المتوقعة داخل ZIP:
  - `jdk/bin/java`
  - `gradle/bin/gradle`
  - `android-sdk/platforms/android-35/android.jar`
  - `android-sdk/build-tools/35.0.0/aapt2`
- يمكن وضع مجلد `mdstudio-toolchain/` كجذر داخل ZIP أو وضع هذه المسارات في جذر ZIP مباشرة.
- بعد الاستيراد، يحاول التطبيق تنفيذ `:app:assembleDebug` ويعرض مسار APK فقط إذا وجد الملف الناتج فعلًا.

## حدود يجب عدم إخفائها

1. تشغيل JDK وGradle وأدوات SDK كعمليات فرعية من تطبيق Android يعتمد على توافق الحزمة مع ABI وإصدار Android وسياسات تنفيذ الملفات في الجهاز. وجود الملفات وحده لا يضمن أن الجهاز يسمح بتشغيلها. لذلك يجب اختبار حزمة الأدوات على الهاتف المستهدف.
2. لا تتضمن هذه الحزمة JDK أو Gradle أو Android SDK أو AAPT2؛ المستخدم يزود حزمة متوافقة. لم يتم تضمين أدوات ضخمة أو ادعاء اختبارها.
3. GitHub Actions لا يعمل بمجرد اختيار المستودع؛ يجب أن يحتوي المستودع على ملف Workflow المشار إليه وأن يكون الرمز مخولًا لتشغيله.
4. صفحة تشغيل Workflow تفتح على GitHub لعرض سجلات التشغيل وتنزيل Artifacts. التنزيل المباشر داخل التطبيق لم يكتمل بعد.
5. استيراد GGUF موجود، لكن الاستدلال المحلي الفعلي لم يكتمل لأن مكتبة llama.cpp الأصلية غير مضمّنة ولا يوجد ملف `libmdstudio_llama.so` مبني لكل ABI.
6. لا تتضمن هذه المرحلة استعادة سورس PocketBuilder الأصلي أو نقل جميع محركاته. ملف APK الأصلي محفوظ كمرجع فقط.

## تشغيل البناء السحابي

1. ارفع مجلد المشروع كاملًا إلى مستودع GitHub.
2. تأكد أن الملف `.github/workflows/mdstudio-build.yml` موجود في الفرع الافتراضي.
3. أضف رمز GitHub من داخل MD Studio، ثم حمّل المستودعات واختر المستودع.
4. افتح تبويب البناء واضغط «تشغيل بناء APK».
5. حدّث حالة البناء. عند ظهور تشغيل، افتح صفحة GitHub الخاصة به، ثم نزّل Artifact باسم `MD-Studio-debug-apk` بعد نجاح البناء.

## حالة التحقق

- تم تعديل المصدر والوثائق وملفات Workflow.
- لم تتوفر Gradle أو Android SDK في بيئة إعداد هذه الحزمة؛ لذلك لم يتم تنفيذ `assembleDebug` هنا.
- لم يتم اختبار اتصالات Gemini أو GitHub بمفاتيح حقيقية.
- لم يتم اختبار JDK/Gradle على جهاز Android فعلي.
- لم يتم تشغيل نموذج GGUF محليًا.
