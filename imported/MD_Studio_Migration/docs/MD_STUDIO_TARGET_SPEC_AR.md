# المواصفات المستهدفة لـ MD Studio

هذه وثيقة تجميع للمواصفات المستقرة المعروفة من تعليمات المستخدم السابقة. هي مواصفات هدف وليست ادعاءً بأن جميع البنود نُفذت في النسخة الأولية الحالية.

## الهوية والنطاق
- اسم المنتج الحالي: MD Studio.
- هوية الاستوديو المطوّر: AMD Studio.
- AI Studio اسم أداة/برنامج عمل فقط، وليس اسم المطوّر أو هوية شهادة توقيع.
- النطاق الأساسي: إنشاء وتطوير تطبيقات Android، مع دعم أكبر مجموعة عملية من لغات البرمجة وأدوات البناء التي يمكن تشغيلها عبر محركات متخصصة.
- عدم الادعاء بأن كل لغة تعمل مباشرة على الهاتف أو يمكن تضمين مترجمها داخل APK.

## الأولويات وطريقة التنفيذ
1. تحسين واجهة الاستخدام وتجربة المستخدم أولًا.
2. بعد إدخال اسم التطبيق وفكرته، يتولى النظام تلقائيًا تجهيز المتطلبات والخطة والملفات والإعدادات بقدر ما تسمح به المحركات المتاحة.
3. يعرض ملخصًا نهائيًا واضحًا، ثم يطلب قرار موافقة واحدًا بدل طلب موافقات متكررة عند كل خطوة.
4. لا تظهر حالة نجاح أو ملف APK نهائي إلا بعد تنفيذ حقيقي والتحقق من النتيجة.
5. للمشروعات الموجودة، تكون التعليمات تحديثًا للمشروع القائم، مع قراءة بنيته أولًا والحفاظ على وظائفه وبياناته وإعداداته وعدم إنشاء نسخ مكررة.

## مصادر ومحركات التنفيذ
- البناء السحابي عبر GitHub Actions هو مسار البناء المعتمد لإنتاج APK.
- GitHub كمصدر للمشروعات والبناء السحابي عبر GitHub Actions، مع دعم أكثر من حساب GitHub.
- مزودو ذكاء اصطناعي متعددون ومفاتيح متعددة لكل مزود، ومنها مفاتيح Google Gemini المتعددة مع حالات واضحة وإدارة الحصص والتبديل المنضبط.
- دعم نماذج محلية مثل Llama عبر محرك محلي متوافق، بما في ذلك نماذج GGUF، دون اعتبار مجرد استيراد الملف دليلًا على أن الاستدلال المحلي يعمل.
- بنية قابلة لإضافة محركات ولغات وأدوات متخصصة دون تشغيل كل الأدوات في وقت واحد أو استهلاك موارد الجهاز بلا حاجة.

## واجهة التطبيق
- أقسام التنقل المستهدفة: المشروعات، الاختبارات، مساحة العمل، البناء، المكتبة، الإعدادات.
- المحادثة هي مركز إصدار الأوامر ومتابعة التنفيذ، ولا ينبغي إجبار المستخدم على التنقل بين الشاشات لكل أمر.
- بطاقة مهمة تعرض الحالة الحقيقية، مع حالات تشغيل واضحة.
- مدير هندسي مركزي ينسق وكلاء التخطيط والمعمارية والواجهات والبرمجة والبيانات والتكاملات وإصلاح الأخطاء والبناء والاختبارات والذاكرة والبحث.
- لا تُضاف حاليًا أداة مصمم واجهات مرئي أو سحب وإفلات أو منشئ وظائف قائم على الاختيارات؛ الأولوية لتطوير محركات البرمجة والتنفيذ المحلية.
- لا تُضاف ميزات توليد الصور أو الفيديو إلى نطاق المنتج.

## الصلاحيات والقدرات
- فصل القدرة التقنية عن الصلاحية الممنوحة: الوضع العادي، Shizuku، Root، وصلاحيات Android الأخرى.
- عدم الادعاء بأن Shizuku يمنح صلاحيات Root.
- فحص البيئة والأدوات المتاحة، ثم إظهار ما يمكن تنفيذه فعليًا وفق الصلاحيات.
- تخطي الفحوص غير الحاسمة أو الفاشلة مع تسجيلها ومواصلة بقية التشخيصات متى كان ذلك آمنًا.

## GitHub والأسرار
- حفظ رموز الوصول ومفاتيح API بصورة آمنة محليًا، وعدم تضمينها في ملفات المشروع أو سجلات البناء.
- دعم مستودعات متعددة وحسابات متعددة، وتشغيل Workflows ومتابعة السجلات وتنزيل ملفات البناء.
- التحقق من صلاحيات الرمز المطلوبة بدل طلب صلاحيات واسعة دون حاجة.

## إدارة التطبيقات الناتجة
- إعداد اسم الحزمة واسم APK بما يتوافق مع اسم التطبيق وقواعد التسمية التي يحددها المستخدم.
- هوية توقيع مستقلة يجهزها المستخدم قبل إصدار APK النهائي.
- اسم الاستوديو المطوّر في التطبيقات: AMD Studio، لا AI Studio.
- إدارة نسخ APK، نتائج الاختبارات، التوقيع، وسجل الإصدارات.

## حالة التنفيذ بعد المرحلة الثالثة

### منفذ في المصدر ولم يُختبر على جهاز
- عدة حسابات GitHub ومفاتيح Gemini مع تخزين مشفر.
- تشغيل GitHub Actions بخيارات Debug/Release وتشغيل الاختبارات، وجلب التشغيلات وArtifacts وتنزيل APK.
- تصدير APK عبر Storage Access Framework.
- استيراد مشاريع Gradle ZIP ومستكشف ملفات ومحرر نصي محدود وتشخيص بنيوي.
- مسار بناء محلي عبر Termux RUN_COMMAND مع إعداد JDK 21 وGradle 8.13 وAndroid SDK/AAPT2 الخاص بـ Termux.
- مسار استدلال GGUF عبر llama.cpp CLI داخل Termux بعد تشغيل سكريبت البناء.
- إعداد توقيع Release اختياري من GitHub Secrets؛ دون شهادة يكون APK Release غير موقّع.

### ما زال غير مكتمل
- لا يزال نقل كل وظائف PocketBuilder الأصلية غير مكتمل؛ ملف APK لا يحتوي مشروع المصدر الأصلي.
- البناء المحلي ودمج Llama ليسا ضمن متطلبات مرحلة إنتاج APK الحالية؛ يعتمد MD Studio على GitHub Actions.
- Llama يعمل عبر Termux CLI في المصدر، وليس JNI مدمجًا داخل APK.
- لم يُنفذ Gradle compilation أو بناء APK أو اختبار جهاز فعلي في بيئة إعداد هذه الحزمة.
- لم يكتمل مدير الوكلاء الذي يحول الفكرة تلقائيًا إلى ملفات مصدر كاملة ثم يطبقها ويختبرها.

كل ميزة أعلاه موصوفة حسب حالتها الحقيقية؛ وجود واجهة أو سكريبت إعداد لا يعني أن التنفيذ اجتاز اختبارًا فعليًا على الهاتف.
