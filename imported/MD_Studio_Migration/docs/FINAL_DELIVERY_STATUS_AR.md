# تسليم MD Studio — تحديث البناء السحابي (v7)

## ما تم استكماله في هذه الدفعة

1. **توليد مشروع بالذكاء الاصطناعي بموافقة واحدة**
   - يرسل اسم التطبيق والحزمة والفكرة إلى Gemini.
   - يستقبل ملخصًا وقائمة ملفات مصدر كاملة.
   - يقيّد الكتابة إلى Kotlin/Java وموارد XML وREADME داخل المشروع.
   - يمنع المسارات الخارجة عن المشروع والمجلدات الحساسة والملفات الثنائية والأسرار.
   - يعرض الملفات والملخص أولًا، ثم يكتبها بعد ضغط المستخدم على «موافقة وتنفيذ».
   - يظل منشئ Gradle الأساسي هو المصدر الموثوق لإعدادات البناء؛ النموذج لا يغيّر Gradle أو Manifest تلقائيًا.

2. **اختبار التطبيق الناتج على الجهاز**
   - إضافة Android FileProvider لمشاركة APK من مساحة MD Studio الخاصة.
   - فتح مثبت Android مع طلب إذن مصادر التثبيت غير المعروفة عند الحاجة.
   - لا يدّعي التطبيق نجاح التثبيت قبل تأكيد المستخدم من النظام.
   - إضافة تشغيل الحزمة وجمع بيانات الإصدار ومسار التثبيت ووقت التحقق.
   - بيانات الحزمة ليست اختبارًا وظيفيًا آليًا ولا تسجيل شاشة.

3. **موصلات خدمات قابلة للتهيئة**
   - Runtime AI وRuntime Search.
   - App Backend وMultiplayer.
   - موصل HTTPS JSON عام بمسارات health/operation يحددها مالك الخدمة.
   - لا توجد خوادم أو مفاتيح إنتاج مضمّنة، ويجب حفظ الرموز عبر Android Keystore عند إعدادها.

4. **تحسينات توافق وحماية**
   - خفض minSdk لتطبيق MD Studio إلى Android 9 (API 28).
   - دعم أسماء تطبيقات عربية في مولد المشاريع.
   - إضافة استعلامات رؤية تطبيقات Launcher وTermux.
   - زيادة مساحة المحتوى لتصبح قابلة للتمرير.
   - رفع versionName إلى 1.0.0-alpha06.

## الوظائف الموجودة من الإصدارات السابقة

- عدة مفاتيح Gemini بتخزين مشفر وتبديل متسلسل.
- حسابات GitHub متعددة، مستودعات، رفع نسخة المشروع إلى فرع مستقل، تثبيت/ترقية Workflow السحابي، تشغيل Actions، متابعة التشغيل وتنزيل APK Artifact تلقائيًا.
- مساحة عمل ومحرر محدود ونسخ استعادة وتشخيص بنية المشروع.
- بحث Maven Central وإضافة اعتماد مع نسخة احتياطية.
- إنشاء مشروع Kotlin/Compose أساسي.

## نطاق البناء في v7

- جعل GitHub Actions مسار البناء المعتمد، وإزالة واجهات البناء المحلي وTermux من مركز البناء.
- توحيد اسم Workflow إلى `mdstudio-build.yml` بين التطبيق والمستودع.
- الاختبارات الوحدوية تُنفّذ على GitHub Actions قبل بناء APK، مع رفع تقاريرها كـ Artifact.
- فحص بنية مشروع Android والتحقق من APK عبر AAPT وAPK Signer قبل رفعه.
- إضافة دعم أسرار التوقيع الاختيارية إلى المشاريع الجديدة التي ينشئها MD Studio.
- لا يحتاج الهاتف إلى تثبيت JDK أو Gradle أو Android SDK.

## ما لا يمكن اعتباره مكتملًا أو منقولًا

- لم يتوفر سورس PocketBuilder الأصلي؛ ملف APK يحتوي كودًا مترجمًا. لذلك لم يتم نقل كل محركات PocketBuilder حرفيًا، بل أعيد تنفيذ مجموعة قدرات من الصفر مع الاحتفاظ بالـAPK مرجعًا.
- محركات خدمات الخلفية وMultiplayer وRuntime AI/Search تتطلب عناوين API ومخططات JSON ومفاتيح من مالك الخدمة؛ تم توفير موصلات عامة وليس خوادم فعلية.
- Llama يعمل عبر Termux CLI، وليس JNI مدمجًا داخل APK.
- مدير الوكلاء ما زال يحتاج ربطًا أوسع بين المحادثة وكل الأدوات؛ مولد المشروع بالذكاء الاصطناعي هو مسار فعلي منفصل بموافقة واحدة.
- لا توجد اختبارات UI آلية أو تسجيل شاشة؛ فحص الجهاز يجمع بيانات النظام والحزمة فقط.
- لم يُنفذ Gradle compilation أو APK build في بيئة إعداد هذا الملف لعدم توفر Android SDK وGradle. نجاح فحوص XML/JSON/YAML والسكريبتات وفحص تركيب Kotlin لا يعادل بناء Android ناجحًا.

## فحوص هذه الدفعة

- XML parsing: ناجح.
- JSON parsing: ناجح.
- YAML parsing: ناجح.
- `bash -n` لسكريبتات Termux: ناجح.
- Kotlin parser scan: لا توجد أخطاء syntax؛ لم تتوفر Android SDK/AndroidX classpath لإكمال compile.
- APK install/build/device test: لم يُنفذ.

## طريقة البناء النهائية

- البناء المعتمد: من مركز البناء داخل MD Studio بعد ربط حساب GitHub واختيار المستودع والمشروع.
- يمكن أيضًا تشغيل `.github/workflows/mdstudio-build.yml` يدويًا من تبويب Actions في GitHub.
- Release موقّع: أضف أسرار التوقيع المحددة في Workflow. لا تستخدم هوية AI Studio؛ هوية الاستوديو هي AMD Studio.


## تحديث v7 — إنشاء المستودع والبناء من خطوة واحدة

- أضيفت عملية إنشاء مستودع GitHub خاص تلقائيًا من داخل مركز البناء، ويُشتق الاسم من `rootProject.name` في Gradle مع لاحقة فريدة عند تعارض الاسم.
- بعد الإنشاء، يستخدم MD Studio المستودع الجديد لرفع ملفات المشروع إلى فرع بناء مستقل، وتجهيز Workflow على الفرع الافتراضي، وتشغيل GitHub Actions، ومتابعة النتيجة وتنزيل APK.
- لا يتطلب ذلك اختيار مستودع مسبقًا، ولا يحتاج الهاتف إلى JDK أو Gradle أو Android SDK.
- الصلاحيات المطلوبة موثقة في `docs/BUILD_AND_TEST_GUIDE_AR.md`. لا توجد حاجة لصلاحية حذف المستودعات.
- هذا تحديث مصدر؛ لم يُنفذ بناء Gradle أو تشغيل GitHub Actions فعليًا لعدم توفر اتصال بحساب GitHub الخاص بالمستخدم ورمزه. يلزم أول تشغيل من حساب المستخدم للتحقق من الاستجابة الفعلية للخدمة.

## تحديث v8 — أتمتة إنشاء مستودع GitHub

- أضيف زر واحد في مركز البناء ينشئ مستودعًا خاصًا جديدًا تلقائيًا اعتمادًا على اسم مشروع Gradle، ثم يبدأ الرفع والبناء السحابي دون الحاجة لاختيار مستودع مسبقًا.
- عند تعارض الاسم، يعيد التطبيق المحاولة باسم فريد. لا يحذف مستودعات ولا يطلب صلاحية حذفها.
- تم تحديث تعليمات صلاحيات GitHub إلى Fine-grained أو Classic token، مع توضيح صلاحية إنشاء المستودع المطلوبة.
- تم تحديث رقم الإصدار إلى `1.0.0-alpha07`.
- اجتازت ملفات XML وJSON وShell وWorkflow فحوص المصدر، وتم تحليل Workflow المضمن داخل كود Kotlin بنجاح. لم تظهر أخطاء Kotlin parser، لكن تعذر إجراء Gradle compile لغياب Android SDK/Gradle واعتماديات Android في بيئة إعداد الحزمة.
- لم يتم تنفيذ اتصال فعلي بحساب GitHub أو إنشاء مستودع حقيقي أو إنتاج APK في هذه البيئة؛ أول تشغيل بعد إدخال رمز المستخدم هو الاختبار العملي المطلوب.
